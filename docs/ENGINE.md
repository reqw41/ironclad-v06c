# Движок ИИ залпов (i8080)

`src/engine/engine.asm` — перевод Z80-движка IRONCLAD (`ref/ironclad-msx/src/z80/fold.asm`
+ `sampler.inc`) на i8080 для Вектора-06Ц. Данные — `src/engine/engine_bss.inc`.
Гейт корректности — дифференциальная сверка с оригиналом `tools/engine_diff/`.

## Один исходник вместо трёх бинарников

У MSX было три бинарника из одного исходника (`IFDEF`): `FOLD.BIN` (SALVO), `FOLDSP.BIN`
(SALVO PLUS, `-DSPRULES=1`), `FOLDBAR.BIN` (BARRAGE, `-DBARRULES=1`). Здесь — один код,
вариант выбирается байтами, которые игра пишет до любого вызова движка:

| флаг | значение | что меняет |
|---|---|---|
| `eng_sp` | 0 — SALVO/BARRAGE, 1 — SALVO PLUS | NSHIPS = 5 или 7; в `eng_explore` проверка буя `BZ(C,R)=3` |
| `eng_bar` | 1 — BARRAGE | в `eng_probesel` вес добивания `6000/CC/need` для ненайденного раненого корабля |

Буфер FA всегда на 1120 байт; `eng_fainit` заполняет все 1120 (SALVO/BARRAGE используют 760).
Прочие `IFDEF SPRULES` оригинала расходятся сами: `probesel` в SALVO PLUS просто не зовётся,
режим 2 в `cand` возникает только внутри `probesel`.

## Подключение

```
ARR_MG  equ ...     ; int16[144]   раскладка BASIC: little-endian, первый индекс
ARR_PH  equ ...     ; int16[12]    меняется быстрее; корабли с 1 (элемент 0 не
ARR_CC  equ ...     ; int16[8]     используется); BZ(C,R), PM(C,R) = база+(C+10R)*2
ARR_OS  equ ...     ; int16[8]
ARR_SZ  equ ...     ; int16[12]
ARR_HK  equ ...     ; int16[8]
ARR_TX  equ ...     ; int16[11]
ARR_TY  equ ...     ; int16[11]
ARR_BZ  equ ...     ; int16[100]
ARR_PM  equ ...     ; int16[100]
ENG_JIFFY equ ...   ; адрес 16-битного счётчика кадров (бывший JIFFY 0FC9Eh):
                    ; из него берётся семя, если ENG_SEED = 0; там 0 -> 0ACE1h
        include "engine.asm"        ; код, без ORG
        ...
        include "engine_bss.inc"    ; в BSS игры (только метки на DS)
```

Всё внутреннее — в модуле sjasmplus `engine` (метки `engine.xxx`), наружу видны только
перечисленные ниже глобальные имена.

**Инициализация.** Движок не полагается на обнуление BSS: `eng_fainit` в начале партии
сбрасывает FA/MO/MC и `vST`, `vKL`, `vRK`. Исключение — `SMEMG/SMEMR/SMEMB`: это сессионные
счётчики (у MSX — от включения питания, BASIC 138 с магической парой DDF3/DDF4), игра
обнуляет их один раз при запуске программы и не трогает между партиями.

## Точки входа

Аргумент USR — в HL; возвращаемого значения игра не использует. Регистры не сохраняются.

| метка | было | кто зовёт (IRONCLAD.BAS) | вход |
|---|---|---|---|
| `eng_fold` | USR0 | 4301 `USR0(NS)` | HL = NS (младшая тетрада) |
| `eng_kill1` | USR1 | 4325 `USR1(KN*256+U*16+V)` | HL = KN·256 + U·16 + V |
| `eng_explore` | USR2 | 4071, перед ним 4070 пишет `vRD`, `vNF`, `vRIM` | — |
| `eng_pickn` | USR3 | 4050, перед ним `vNF` (и, возможно, `vKL`) | — |
| `eng_marg` | USR4 | BASIC не зовёт (DEFUSR4 нет); внутренний откат `sample` | — |
| `eng_sample` | USR5 | 4012 (SALVO/BARRAGE), 4013 (SALVO PLUS) | — |
| — | USR6 `samp1` | никто (DEFUSR6 нет; в FOLDBAR — заглушка) — **выброшен** | |
| `eng_fainit` | USR7 | 4098 | — |
| `eng_probesel` | USR8 | 4012 (только SALVO/BARRAGE; в SALVO PLUS не зовётся) | — |

`exact.inc` (точный перебор) в оригинале **не подключён** ни в один из трёх бинарников
(`fold.asm` не делает `include "exact.inc"`, символ `pMO` не определён, собранные бинарники
побайтно равны релизным) — мёртвый исходник, не переводился.

## Экспортируемые данные и бывшие адреса MSX

| символ | бывший адрес | как игра им пользуется (строки BASIC) |
|---|---|---|
| `vRD` | 0CF98h (PARM+32) | 4070 `POKE &HCF98,RD` перед `eng_explore` |
| `vNF` | 0CF99h (PARM+33) | 4070, 4050 `POKE &HCF99,NF` перед `eng_explore`/`eng_pickn` |
| `vRIM` | 0CF9Ah (PARM+34) | 4070 `POKE &HCF9A,-(R8=1 AND SN<14)` |
| `vKL` | 0CFABh (PARM+51) | 4004, 4010, 4015 `POKE &HCFAB,KL` / `,255` (обнуляет `eng_pickn`) |
| `vRK` | 0CFFAh (PARM+130) | 4009 `POKE &HCFFA,0/1` (только SALVO/BARRAGE) |
| `ENG_MC` | 0D098h (MCBUF) | 4102 `POKE &HD0A5+C*12+R` = `ENG_MC+13+C*12+R`; 4338 `PEEK(&HD098+P9)` |
| `ENG_FA` | 0D128h (FABUF) | 4321 `PEEK(&HD128+I)` = `ENG_FA+I` |
| `SMEMG` | 0DDF0h | 138, 4103-4105, 4107 |
| `SMEMR` | 0DDF1h | 138, 4104-4105, 4109 |
| `SMEMB` | 0DDF2h | 138, 4107, 4109 (движок читает в `eng_explore`) |
| `ENG_SEED` | 0CFAEh (PARM+54, vSEED) | BASIC не трогал; игра может задать семя (0 — взять из `ENG_JIFFY`) |
| `eng_sp`, `eng_bar` | — (были разные бинарники) | пишет игра по набору правил |

Остальные переменные PARM (`vH`…`vNEED`) — внутренние, в том же порядке, что в оригинале
(кроме `vST`: он стоит сразу за MO), но без указателей на массивы BASIC (`pBASE`…`pPM`,
`setptrs` больше нет: массивы по `ARR_*` адресуются напрямую). Новый внутренний байт один —
`vSMC` (режим общего `mgseedx`, который заменил `mgseed` и `mgseedmc`). Плоскости лежат
подряд FA, MC, MO, `vST` — на этом держатся `eng_fainit` (одно заполнение) и `bumpst`
(ASSERT в `engine_bss.inc`); там же ASSERT соседства пар `vC`/`vR`, `vBX`/`vBY`, `vGG`/`vSA`,
которые код читает и пишет словом.

## Размер

| | байт |
|---|---|
| код `engine.asm` | **1882** (было 2684 — перевод на скорость; оригиналы 2119–2510 каждый, три вместе 7109) |
| данные `engine_bss.inc` | **1522** (переменные PARM 108 + новая 1 + флаги 2 + FA 1120 + MC 144 + MO 144 + SMEM 3) |
| стек | 24 (с адресом возврата вызова; прерывание игры — сверху; было 18) |

Движок ужат по размеру ценой скорости (скорость хода не требуется, образ игры не влезает
в память). Что сделано и сколько дало, по шагам (байты кода):

| приём | байт |
|---|---|
| `kill1`: вместо своего убийцы (`kc`, `krange`, `mul8`, `kfa`) — тот же `cand` режима 0 для живых двух строк FA; `klast` и `decode` делят `jdec`; `scan` — две половины через общий перебор строк; `pidx`/`mapptr` в байте | −276 |
| общие подпрограммы: элемент по номеру корабля (`kel`/`kel16`), `scanwt`/`scanm`, `crun` (три прохода по клеткам кандидата), `mgat`; `clrmap` ставит vMODE; `fainit` одним заполнением; `bumpst` через `inc (hl)` | −96 |
| `pickn` — простой перебор с `sgt` (как у оригинала) вместо указателя и счёта в регистрах; `explore`/`mgseedx` — общие `mc8`/`jadd`; запись TX/TY — `stnext` | −142 |
| сэмплер: `sortso` на указателях; `pldraw` зовёт `rnd16` в цикле отбраковки (одна копия xorshift); метка MO — три линии; две никогда не срабатывающие ветви убраны | −95 |
| `nsh` вместо пролога `setup` и байта `vNS1`; порядок BSS FA-MC-MO-vST; `jdec` одним делением; C/R и BX/BY словом; `candmg` через `crun`; `pldraw` считает J0 в регистре | −63 |
| `div16` — повторное вычитание, как у оригинала (18 байт вместо 37) | −23 |
| общий перебор лучшей клетки P9 = 13..130 (`p9best`) для `pickn` и `probesel` | −21 |
| индекс `klast` на стеке (без `vKI`), `famw` без сохранения BC, `pldraw` проваливается в `decode` | −19 |
| CC−1 через `kel16`/`dec de`; \|2n−CC\| вычитанием с хвостом в `sgt1`; общий хвост `mapptr`/`mgat` | −13 |
| общие переборы `fork` (K = 1..NSHIPS: fold, marg, probesel) и `forcr` (C, R с PM = 0: explore, mgseedx) — выходы обработчиков стали `ret`, хвостовые вызовы `jp` | −18 |
| мелочи: `fmark` по базам −2, лишние `xor a`/`or a`, `famw` умножает циклом по W, короче `divsm`, `mapptr` глотает `add hl,hl` байтом `cp n`, блоки переставлены под проваливание | −36 |

Не сделано (не окупается): вернуть `kill1` к оригиналу (метка + полный scan) — ещё ≈ −115 Б,
но 48 тыс. тактов на вызов × 378 вызовов = худший ход ≈ 6 с; `fill2` вместо `fill4` — −4 Б
на подпрограмме, +3 Б лишнего вызова в `fainit`; запись `vSTEP` одним байтом — +1…+4 Б
(старший байт всё равно надо писать); `candmg` без `crun` ради стека 22 вместо 24 — +6 Б;
`rimchk` через общую проверку клетки края — +5 Б; быстрая копия xorshift в `pldraw` (стресс
`sample` 4.5 → ≈2.7 с на случайных состояниях) — +26 Б.

## Отличия от оригинала (итоговое состояние то же — доказано сверкой)

Перевод дословный по смыслу и по всем выходным данным, включая рабочие переменные PARM.
Меняется только способ счёта, не меняя результата:

* `scan` — мёртвые кандидаты (FA=0) пропускаются прямо в цикле (указатель FA в HL, индекс
  клетки в E); `cand` зовётся только для живых. Итоговые vFAP/vSTEP/vLK/vW как у оригинала.
* `kill1` — не прогоняет scan по всем 20W кандидатам, а зовёт тот же `cand` (режим 0, та же
  карта с одной клеткой) для живых из двух строк FA, где лежат все покрывающие клетку: строка
  Y = y0 поперёк и столбец X = x0 вниз (по W кандидатов); непокрывающих отсеивает сумма карты.
  vIDX оригинал писал для КАЖДОГО живого кандидата до проверки — здесь это индекс последнего
  живого кандидата корабля до снятия (`klast`), vFAP = FA(OS+20W), vSTEP = 1. Вызов —
  13 тыс. тактов (оригинальный полный scan — 48 тыс.); распространение после находки корабля
  (до ~380 вызовов за ход в SALVO PLUS) остаётся основной долей худшего хода.
* `pickn`, `probesel` — общий перебор лучшей клетки `p9best` (P9 = 13..130, vBS/vBXW/vP9 как
  у оригинала), клетку оценивает обработчик.
* `fold`/`marg`/`probesel` и `explore`/`mgseedx` — тела циклов оригинала стали обработчиками
  общих переборов `fork` (K = 1..NSHIPS) и `forcr` (C, R = 0..9, клетки с PM = 0); в конце
  vK = NSHIPS+1, vC = vR = 10, как у оригинала. `explore` пишет vP9 = 131 в конце (оригинал
  вёл его по клеткам и кончал там же).
* `div16` — повторное вычитание, как у оригинала (время растёт с частным: 2880/1 — 2880 шагов
  по 32 такта). При делителе 0 оригинал зависал (BARRAGE `probesel`, раненый корабль с CC=0 —
  вне инвариантов игры), перевод вернёт 0.
* `mgseed`/`mgseedmc` слиты в `mgseedx` (A=0 — дрожание, A=1 — MC·8+дрожание).
* метка соседей в `place` — три линии по LK+2 клеток от IB−13 с шагом S9 (то же множество
  клеток, что p, p−W2, p+W2 оригинала; vW2 пишется).
* `fmark` метит выстрелы с последнего (порядок меток карты не важен).
* заполнение памяти — развёрнуто по 4 байта (`fill4`).
* `rnd16` повторяет генератор оригинала точно, включая его особенность: сдвиг «x<<7» урезан
  до младшего байта (`H ^= L>>1; L ^= (L&1)<<7`).

Две ветви оригинала, не срабатывающие никогда по построению, выброшены: `ret z` в `onesamp`
(после удачной выборки QNC = сумма длин кораблей, не 0) и `jr c,plrgive` в `place`
(перерисовка идёт после удачного pldraw, CC не менялся — живой кандидат есть). Все условные
переходы перевода теперь проходятся стендом в обе стороны.

## Гейт: дифференциальная сверка

```
node tools/engine_diff/run.js                 # ~35 с: 12 сессий + 400 случайных на вход
node tools/engine_diff/run.js --sessions 30 --random 1000   # ~90 с, 100 тыс. вызовов
node tools/engine_diff/mutate.js              # ~2.5 мин (8 потоков): стенд не слеп
node tools/engine_diff/run.js --profile       # такты по подпрограммам
```

Код выхода 0 — гейт пройден. Нужен только node (python не нужен); эмуляторы — копии из vector06js
в `tools/engine_diff/vendor/` (i8080.js — ядро vector06js, Z80_v06.js — M. Howell).

**Что сравнивается.** Одно и то же состояние загружается в обе стороны:

* Z80-оригинал: `FOLD.BIN` / `FOLDSP.BIN` / `FOLDBAR.BIN`, собранные из `ref/ironclad-msx`
  тем же sjasmplus в `build/diff/orig/` и **побайтно равные** бинарникам на
  `release/IRONCLAD.DSK`; массивы по смещениям `offsets*.inc` от ARYTAB+8, указатель ARYTAB
  в 0F6C4h, аргумент в 0F7F8h, PARM/MO/MC/FA/SMEM по адресам из `.sym` оригинала.
* i8080-перевод, собранный с `--i8080` (ассемблер отвергает всё не-8080), массивы по ARR_*,
  аргумент в HL.

После вызова сравниваются все массивы (MG, PH, CC, OS, SZ, HK, TX, TY, BZ, PM — у Вектора их
элементы сверх размерностей MSX обязаны остаться нетронутыми), MO, MC, FA (760 байт у
SALVO/BARRAGE — дальше у MSX код; хвост 760..1119 у перевода меняет только `eng_fainit`),
**все 45 переменных PARM** (указатели vFAP/vSOP — относительно своих буферов), SMEM. Плюс
запись за пределы своих данных и порча кода — у обеих сторон; зависание; сход стека.

**Второй эталон.** У MSX `TX(4)` — не больше 5 выстрелов, у Вектора `TX[11]`. Чтобы сверить
залпы 6..11 (SALVO PLUS с SV=1), неизменённые `fold.asm`/`sampler.inc` собираются ещё раз с
«широким» `offsets.inc` (TX/TY по 11; BUILDING.md так и велит при изменении массивов) — в
таблице эти строки со звёздочкой.

**Состояния.**

* Модель вражеской стороны BASIC (`model.js`): расстановка флота без касаний (35% партий —
  с тягой к краю), 4097–4110 (начало партии, SMEMB из счётчиков), 3840–3857 (ход врага,
  попадания 910–981), 4000–4096 (случайное начало, разведка, добивание, вердикт края vRK,
  E9/255), 4300–4339 (свёртка, распространение с kill1, буи 3, мёртвая вода). Партии идут до
  потопления флота, по 1–3 партии в сессии (счётчики SMEM и семя живут между партиями).
  R8 («личность — край») в этой версии BASIC всегда 0 — модель включает её в 30% партий для
  покрытия vRIM.
* Случайные состояния (`randomState`) — в пределах инвариантов, при которых оригинал не
  выходит за свои данные: CC = числу живых флагов (нужно pldraw), флот — перестановка
  настоящего, TX/TY в −1..11, U/V kill1 — любые тетрады, «застоявшиеся» vBX/vBY/vBXW — в поле.
  Вне этих рамок сравнивать нечего (оригинал читал бы заголовки массивов BASIC или свой код);
  стенд считает такие случаи отдельно — их 0.

**Покрытие перевода:** метки 122/122, команды 1023/1023, условные переходы в обе стороны
87/87.

**Мутационная проверка** (`mutate.js`): 47 намеренных ошибок в копии перевода — все пойманы
расхождениями (не падением покрытия): сравнения и знаки в pickn/sgt/explore/probesel, флаги
(потерянный `ccf`, `sbc→sub` в sgt1 и в CC−2n, заём в \|2n−CC\| и в CC−1, `rrca→rra`,
`adc→add` в candmg и +12000), маска NS, оси mapptr, шаги строк shalf и jdec, отсев cand,
пропуск живого в scan, отсев PM в forcr, fork с K=2, все ветки kill1 (деление клетки на 12 —
перенос V+1 ≥ 12 в соседний столбец, строка вниз 10+x0, отсечка x0 < 10, строка поперёк,
klast, восстановление vIDX), pickn (новый лучший без BXW, X со знаком, −9, первый корабль
у 255), div16 (частное +1, делитель без +1), константы весов, NSHIPS, буй SALVO PLUS,
выборка (pldraw: отбраковка и r+1, семя из ENG_JIFFY, place, sortso, запись P9, 3 линии
метки, число попыток sample), fainit. Гейт падает на пустой выборке.
Три мутации первой версии оказались эквивалентными и заменены: `or a` перед `rra` (CY уже
сброшен `xor` — убран из кода), 6000→6001 (отличается лишь при CC, делящем 6001), и маска
NS 0Fh→07h — она была настоящей слепой зоной (NS ≤ 5 у MSX) и закрыта вторым эталоном.
При ужатии мутации переписанных мест заменены равноценными по месту в новом коде; две
(«семя не сохранено», «SA не уменьшается») зацикливали выборку до предела стенда — заменены
